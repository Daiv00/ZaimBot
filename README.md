# Telegram бот для заявок — без базы данных

Эта версия специально сделана без PostgreSQL.

Схема работы:

Заемщик → бот → админский Telegram-чат.

В админский чат отправляются:
- все заполненные поля;
- фото паспорта;
- фото регистрации;
- селфи с паспортом;
- кнопки «Одобрить», «Отказать», «Выдано».

## Что нужно указать на Render

### Build Command
```text
pip install -r requirements.txt
```

### Start Command
```text
uvicorn bot:app --host 0.0.0.0 --port $PORT
```

### Environment Variables

`BOT_TOKEN` — токен от @BotFather.

`ADMIN_CHAT_ID` — ID чата, куда бот будет отправлять заявки.
Например:
```text
-1001234567890
```

`ADMIN_IDS` — Telegram ID администраторов через запятую.
Например:
```text
123456789,987654321
```

`COMPANY_NAME` — название компании.

`COMPANY_INN` — ИНН, необязательно.

`COMPANY_ADDRESS` — адрес компании, необязательно.

`WEBHOOK_SECRET` Render сгенерирует автоматически через render.yaml.

`PORT` вручную задавать НЕ надо.

`DATABASE_URL` больше НЕ нужен.

## Как узнать ADMIN_CHAT_ID

1. Добавьте бота в нужную группу.
2. Напишите в группе любое сообщение.
3. Используйте @RawDataBot или другой способ получения ID чата.
4. Для группы/супергруппы ID обычно начинается с `-100`.

Бот должен быть участником чата и иметь возможность отправлять сообщения и документы.

## Важно

В этой версии нет базы данных. Источником истории заявок является Telegram-чат администратора.

Текущие заявки хранятся в памяти процесса, поэтому после перезапуска Render старые интерактивные кнопки могут перестать работать. Сами сообщения и документы уже останутся в Telegram-чате.

Файлы временно сохраняются в `/tmp` только для передачи Telegram/создания PDF и не являются постоянным хранилищем.

Для реального кредитного бизнеса паспортные данные и селфи — очень чувствительные данные. Перед использованием в продакшене нужны соответствующие меры защиты, сроки хранения и удаление данных по правилам вашей юрисдикции.

PDF договора является техническим шаблоном и не является юридической проверкой договора.

## Python version

Python is explicitly pinned to `3.12.8` in `render.yaml` and `.python-version`.
Do not remove this setting. It prevents Render's current Python 3.14 default from
trying to compile incompatible dependency versions during deployment.
